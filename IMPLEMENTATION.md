## 6. IMPLEMENTATION

### 6.1 Architecture Overview
The AI Interview Platform is built utilizing a heavily decoupled, server-client architecture. The architectural philosophy prioritizes keeping the client browser completely unblocked while maintaining highly intensive computations (such as raw video processing and natural language indexing) entirely on dedicated asynchronous backend environments.

### 6.2 Technology Scope
Our platform utilizes a highly specialized suite of frameworks and libraries to manage the high data volume and processing requirements.

#### 6.2.1 React.js & TypeScript (Frontend Layer)
The presentation layer is explicitly structured using React.js and TypeScript. We utilize React's custom hooks and Context API to seamlessly stream real-time camera data from the user's hardware via the `MediaRecorder` API. TypeScript ensures that the heavily nested feedback metrics fetched from the server are strictly verified at compile-time, eliminating frontend rendering crashes.

#### 6.2.2 Node.js & Express.js (API Gateway)
Handling authentication, HTTP state management, and file routing is accomplished through Node.js. Given the asynchronous nature of Express.js, the backend can receive multi-megabyte video blobs from varying simultaneous users, securely buffer them to the object storage, and register database payloads without stalling the primary event loop. 

#### 6.2.3 Python Scientific Stack (AI Evaluation Engine)
All behavioral quantification algorithms are authored in Python. We bypassed external, expensive third-party APIs by building custom analytical scripts. The environment relies strictly on open-source mathematical and scientific libraries (such as `NumPy` for matrix manipulation, `OpenCV` for image frame dissection, and NLP toolkits) to assign deterministic, calculable scores to a candidate's visual and verbal performance.

#### 6.2.4 PostgreSQL (Relational Data persistence)
A normalized relational state management system is critical for linking a user to their diverse historical data. Using PostgreSQL, we aggressively map B-Tree indexed Foreign Keys between the candidate's account, their parsed resume skill vectors, and their detailed interview feedback scores.

#### 6.2.5 Supabase Object Storage (Media Management)
Raw data files—specifically user-uploaded PDF resumes and massive `.webm`/`.mp4` interview recordings—are entirely offloaded to Supabase Storage. The node layer intercepts the client payload, encrypts it, transmits it to the bucket, and writes only the retrieval URI to the PostgreSQL table.


### 6.3 Core System Modules & Sub-systems
The system operations are broadly categorized into targeted functional micro-modules.

#### 6.3.1 Secure Authentication & Session Management
All API routes are guarded by standard JSON Web Token (JWT) verification protocols coupled with BCrypt password hashing. When a user requests data from their dashboard, the authorization headers are decrypted, verifying the candidate’s tenant ID against the database records before returning their analytical data.

#### 6.3.2 Resume Parsing and Information Extraction Module
When a candidate uploads a PDF, the system extracts the raw text buffers. Utilizing string-matching heuristics and regular expressions, the engine maps discovered text strings against an internal dictionary of over 500 recognized technical and soft skills, saving the matches to the database.

#### 6.3.3 Dynamic Interview Question Selection
Using the skill arrays generated by the parsing module, the SQL database constructs complex `IN()` queries to pluck contextually relevant questions. If a candidate's resume parses for "Java" and "Algorithms," the system exclusively queries the question bank matching those exact tags, constructing a highly tailored interview prompt set.

#### 6.3.4 Real-time WebRTC Video Capture System
This module requests the specific `getUserMedia` hardware permissions in the browser to tap the webcam and microphone. The chunks are captured utilizing `MediaRecorder` every 2000 milliseconds, maintaining a localized buffer to prevent data loss in case of a temporary browser delay or internet lag.

#### 6.3.5 Asynchronous Video Processing Pipeline
Completed video blobs are relayed from the client directly to the Node.js API boundary. To prevent socket timeouts during rigorous AI processing, the Node server instantly responds with a HTTP 202 (Accepted) flag, then spawns the Python analyzer silently in the background via asynchronous child processes.

#### 6.3.6 Python Computer Vision (CV) Pipeline
The CV sub-system iterates through the video array frame-by-frame. It isolates the region of interest (the candidate's face) and tracks coordinate drift. Excessive shifts on the X/Y axes are computationally penalized and tagged as "restlessness," while pupil vectors away from the camera lens are penalized as poor "gaze stability."

#### 6.3.7 Python Natural Language Processing (NLP) 
The script maps the transcribed candidate audio into tokenized arrays. Filler words ("uh", "um", "like") are aggressively targeted and quantified. Furthermore, semantic similarity thresholds are checked to ensure the candidate's verbal response correlates logically with the technical question prompted on the screen.

#### 6.3.8 Dashboard Aggregation Engine
A reporting module aggregates the raw data metrics. It averages the confidence scores and organizes data structures specifically formatted for ingestion by the frontend visualization charting libraries.


### 6.4 Detailed Source Code Implementations

#### 6.4.1 React Context API for Video State Management (Frontend)
To efficiently manage the video blobs before submission, we engineered a custom hook interacting with the browser's MediaRecorder interface:

```typescript
// src/hooks/useCameraRecorder.ts
import { useState, useRef, useCallback } from 'react';

export const useCameraRecorder = () => {
    const [isRecording, setIsRecording] = useState(false);
    const mediaRecorderRef = useRef<MediaRecorder | null>(null);
    const recordedChunksRef = useRef<BlobPart[]>([]);

    const startRecording = useCallback(async () => {
        const stream = await navigator.mediaDevices.getUserMedia({ video: true, audio: true });
        mediaRecorderRef.current = new MediaRecorder(stream, { mimeType: 'video/webm' });
        
        mediaRecorderRef.current.ondataavailable = (event) => {
            if (event.data.size > 0) {
                recordedChunksRef.current.push(event.data);
            }
        };
        
        mediaRecorderRef.current.start(2000); // Trigger data event every 2 seconds
        setIsRecording(true);
    }, []);

    const stopAndSubmit = useCallback(async () => {
        mediaRecorderRef.current?.stop();
        setIsRecording(false);
        const finalBlob = new Blob(recordedChunksRef.current, { type: 'video/webm' });
        
        // Dispatch FormData to Node backend
        const fd = new FormData();
        fd.append('interview_video', finalBlob, 'response.webm');
        await fetch('/api/upload', { method: 'POST', body: fd });
    }, []);

    return { startRecording, stopAndSubmit, isRecording };
};
```

#### 6.4.2 Resume PDF Text Extraction Logic (Backend Node.js)
Parsing logic runs securely behind the API wall, shielding the client from heavy processing. 

```javascript
// services/resumeParser.js
const pdfParse = require('pdf-parse');
const db = require('../config/database');

// Internal static dictionary for keyword mapping
const TECH_SKILLS = ['react', 'python', 'java', 'sql', 'docker', 'machine learning'];

exports.extractAndStoreSkills = async (pdfBuffer, userId) => {
    // Extract raw text strings from binary PDF
    const data = await pdfParse(pdfBuffer);
    const rawText = data.text.toLowerCase();
    
    // Initialize parsed arrays
    let detectedSkills = [];
    
    // String matching heuristic loop
    TECH_SKILLS.forEach(skill => {
        if (rawText.includes(skill)) {
            detectedSkills.push(skill);
        }
    });

    // Store mapped skills to relationally linked PostgreSQL table
    await db.query(
        'UPDATE users SET parsed_skills = $1 WHERE id = $2',
        [JSON.stringify(detectedSkills), userId]
    );
    
    return detectedSkills;
};
```

#### 6.4.4 Transcribed Speech Scoring Algorithm (Python NLP)
Linguistic logic searches for hesitation and poor verbal structure.

```python
# ai_engine/speech_analyzer.py
import re

FILLER_DICTIONARY = ["um", "uh", "like", "you know", "basically", "literally"]

def analyze_linguistic_confidence(transcription_text):
    text_lower = transcription_text.lower()
    total_words = len(text_lower.split())
    
    filler_occurrences = 0
    
    # Regular expression counts across transcription payload
    for filler in FILLER_DICTIONARY:
        matches = re.findall(rf"\b{filler}\b", text_lower)
        filler_occurrences += len(matches)
        
    # Penalty weight calculation: If > 5% of speech is fillers, score drops heavily
    filler_ratio = filler_occurrences / max(1, total_words)
    confidence_penalty = filler_ratio * 400  
    
    base_confidence = 100.0
    final_score = max(0.0, base_confidence - confidence_penalty)
    
    return {
        "wordCount": total_words,
        "fillersUsed": filler_occurrences,
        "structuralConfidence": round(final_score, 2)
    }
```

#### 6.4.5 Relational Strict Foreign Keys (PostgreSQL)
We established robust data integrity, preventing orphaned feedback metrics if a user decides to delete their candidate profile.

```sql
-- Database Migration File: Core Architecture
CREATE TABLE IF NOT EXISTS users (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    email VARCHAR(255) UNIQUE NOT NULL,
    parsed_skills JSONB DEFAULT '[]', -- Scalable unstructured storage
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE IF NOT EXISTS interviews (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    user_id UUID NOT NULL,
    video_storage_path TEXT NOT NULL,
    question_prompted TEXT NOT NULL,
    CONSTRAINT fk_user
        FOREIGN KEY(user_id) 
        REFERENCES users(id)
        ON DELETE CASCADE -- Strict cleanup enforced
);

CREATE TABLE IF NOT EXISTS computed_feedback (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    interview_id UUID NOT NULL,
    gaze_score DECIMAL(5,2) NOT NULL,
    linguistic_score DECIMAL(5,2) NOT NULL,
    CONSTRAINT fk_interview
        FOREIGN KEY(interview_id)
        REFERENCES interviews(id)
        ON DELETE CASCADE
);

CREATE INDEX idx_user_interviews ON interviews(user_id);
```
